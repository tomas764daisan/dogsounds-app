# Contributing to DogSounds App

We welcome and appreciate your contributions to the DogSounds App! By contributing, you help us build a better and more enjoyable experience for everyone who loves dog sounds.

## Contribution Guidelines

To ensure a smooth and effective collaboration, please review the following guidelines:

* **Be Respectful**: Treat all contributors and users with respect. Harassment, discrimination, or any form of negative behavior will not be tolerated.
* **Clear Communication**: Clearly describe your changes, issues, or feature suggestions. Provide as much detail as possible.
* **Code Quality**: Write clean, well-commented, and maintainable code. Follow existing coding styles.
* **Testing**: If you're adding new features or fixing bugs, consider adding or updating relevant tests.
* **Documentation**: Update documentation (like README.md) where necessary to reflect your changes.

## How to Contribute

1.  **Fork the Repository**: Start by forking the `dogsounds-app` repository to your GitHub account.
2.  **Clone Your Fork**: Clone your forked repository to your local machine:
    ```bash
    git clone [https://github.com/YOUR_USERNAME/dogsounds-app.git](https://github.com/YOUR_USERNAME/dogsounds-app.git)
    cd dogsounds-app
    ```
3.  **Create a New Branch**: Create a new branch for your specific feature or bug fix. Use a descriptive name (e.g., `feature/add-play-button`, `bugfix/audio-glitch`).
    ```bash
    git checkout -b your-branch-name
    ```
4.  **Make Your Changes**: Implement your changes, write tests, and update documentation as needed.
5.  **Commit Your Changes**: Commit your changes with a clear and concise commit message.
    ```bash
    git commit -m "feat: Add new husky bark sound"
    ```
    * **Commit Message Convention**: We encourage using conventional commits (e.g., `feat:`, `fix:`, `docs:`, `chore:`) for better commit history.
6.  **Push to Your Fork**: Push your new branch to your forked repository on GitHub.
    ```bash
    git push origin your-branch-name
    ```
7.  **Open a Pull Request (PR)**: Go to the original `dogsounds-app` repository on GitHub and open a new Pull Request.
    * Provide a clear title and detailed description of your changes.
    * Reference any related issues.
    * Ensure your PR targets the `main` branch.

## Reporting Issues

Found a bug or encountered an unexpected behavior? Please report it!

1.  Go to the "Issues" tab on the GitHub repository.
2.  Click "New issue".
3.  Provide a clear and descriptive title.
4.  In the description, include:
    * **Steps to reproduce**: How can we replicate the issue?
    * **Expected behavior**: What should have happened?
    * **Actual behavior**: What actually happened?
    * **Screenshots/Videos**: (Optional but helpful) Visuals that demonstrate the issue.
    * **Browser/Device**: (If applicable) Which browser and device are you using?

## Suggesting Features

Have a great idea for a new feature or improvement? We'd love to hear it!

1.  Go to the "Issues" tab on the GitHub repository.
2.  Click "New issue".
3.  Choose the "Feature request" template (if available) or create a new issue.
4.  Provide a clear and descriptive title.
5.  In the description, explain:
    * **The problem**: What problem does this feature solve?
    * **The solution**: How do you envision this feature working?
    * **Benefits**: What are the advantages of adding this feature?

## Code of Conduct

Please note that this project is released with a Contributor Code of Conduct. By participating in this project, you agree to abide by its terms. We are committed to fostering an open and welcoming environment.

## Review Process

Once you submit a pull request, it will be reviewed by the project maintainers. They may:

* Provide feedback and suggest changes.
* Request additional information or clarification.
* Approve and merge your changes into the `main` branch.

Please be patient during this process, and be open to feedback!
